# Smart Campus Room Availability Checker

## Project
- This is a React + TypeScript + Vite availability-only demo for one fictional room (A101).
- `src/App.tsx` renders the form and feedback. `src/data/roomFixture.ts` owns fictional data.
- `src/utils/availability.ts` owns pure booking rules; `src/utils/time.ts` converts display times.
- `tests/availability.test.mjs` provides regression checks; `tests/fixtures/` holds intentionally faulty variants from Practice 08.

## Acceptance contract (AC1-AC6)
- AC1: start/end are integer minutes, `0 <= start < end <= 1440`, and `start > currentTime`.
- AC2: maximum duration is 120 minutes; exactly 120 is allowed.
- AC3: a blocked room is never available.
- AC4: reject actual overlaps; intervals that only touch endpoints are allowed.
- AC5: do not mutate any existing booking or fixture; show Available/Unavailable clearly.
- AC6: use clear validation feedback and retain the responsive desktop/mobile layout.

## Scope and engineering boundaries
- Preserve the existing UI, one-room workflow, fiction-based fixed initial time, and user-visible messages.
- Do not add a backend, database, login, payment, room selection, or booking creation/persistence.
- Prefer pure functions and the smallest change. Use at most two design patterns, only with evidence of need.
- No Strategy with one live booking policy; no Adapter if all booking inputs use `{start, end}`.
- Do not weaken or remove existing tests. The `bug-a` and `bug-b` files are deliberately incorrect historical fixtures.
- Do not claim this file was read automatically by Bolt.new; explicitly include it in the Bolt chat.

## Commands
- `npm ci` - install dependencies.
- `npm test` - run the current acceptance/regression tests (Node 24+ used here).
- `npm run typecheck` - check TypeScript types.
- `npm run lint` - check code style and common errors.
- `npm run build` - create the production preview in `dist/`.
- `npm run dev -- --host 0.0.0.0` - start the local Vite preview.
